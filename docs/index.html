Security

纵深防御的安全沙箱

基于 Windows 原生 Job Objects 与 Linux namespaces/cgroups 构建的多层隔离，让不可信代码在受控环境中运行。

01

进程树隔离

CREATE_SUSPENDED + Job Object 绑定，杜绝竞态逃逸。

02

强制回收

KILL_ON_JOB_CLOSE，主进程结束则整棵进程树被系统强制秒杀。

03

禁止脱离

禁用 BREAKAWAY，子进程无法脱离沙箱。

04

权限降级

受限令牌剥离 SeDebug / SeImpersonate 等高危特权，Low IL 运行。

05

资源限制

内存上限、CPU 时间限制双重保障。

06

数据隔离

每次判题独立临时目录，结束后暴力删除。

07

Linux 隔离

namespaces（user/mnt/pid/net/ipc/uts）+ seccomp + 只读挂载 + RLIMIT 资源限制，能力与 Windows 侧对齐；评测前能力预检，在限制非特权 user namespace 的加固环境自动降级，不中断评测。

08

信任边界

题目代码经完整沙箱隔离执行；SPJ/生成器/grader 以可信（放宽隔离）模式运行并保留时限，导入携带此类代码的题目包时显式告警。

Quick Start

快速开始

编译项目并开始使用 CliJudge。

# 0. 安装（推荐 npm，需 Node.js ≥ 14，自动安装对应平台预编译二进制）
npm install -g clijudge

# 0b. 或从 Release 下载：clijudge.exe / clijudge-linux.bin
#     https://github.com/dxxjudges/clijudge/releases

# 1. 或从源码构建
git clone https://github.com/dxxjudges/clijudge.git
cd clijudge
mkdir build && cd build && cmake .. && cmake --build .

# 2. 查看帮助（Linux 下可执行文件为 ./clijudge）
./clijudge.exe help

# 3. 创建题目
./clijudge.exe problem create "A + B Problem"

# 4. 添加测试数据
./clijudge.exe problem testdata 1 create input.in output.out 1000 256 100

# 5. 提交解答
./clijudge.exe problem submit 1 solution.cpp
  1. 安装：npm install -g clijudge（需 Node.js ≥ 14，含双平台预编译二进制），或在 Releases 下载 clijudge.exe / clijudge-linux.bin，或克隆源码自行编译
  2. 源码编译需 MinGW-w64 + CMake（Windows）或 g++（Linux），亦可按下方 g++ 单命令直接编译
  3. 运行 ./clijudge.exe help 查看帮助
  4. 创建题目、添加测试数据并提交评测

FAQ

常见问题

如何安装 CliJudge？

推荐 npm install -g clijudge 一键安装（需 Node.js ≥ 14，自动安装对应平台预编译二进制）。也可在 Releases 下载 clijudge.exe（Windows）或 clijudge-linux.bin（Linux，重命名后加执行位）直接使用；或克隆源码编译：Windows 用 CMake + MinGW-w64（mkdir build && cd build && cmake .. && cmake --build .），Linux 用 g++ -std=c++17 -O2 -Wall -I include -o clijudge src/main.cpp。

支持哪些编程语言？

内置 C / C++ / Python / Java / JavaScript 五种语言，按提交文件扩展名自动识别；还可通过 judge.custom_languages 注册任意自定义语言。

如何添加测试数据？

使用 problem testdata [题目编号] create [in路径] [out路径] [时间限制] [内存限制] [分值] 命令添加测试点。

什么是测试点生成器？

创建/编辑题目时用 -generator [源码或程序路径]（或 -generator-exe [路径]）附带生成器。每次评测前按测试点编号运行（如 gener.exe 1），生成器在工作目录写入 data.in 与 data.out，作为该测试点的输入与标准答案；testdata create - - ... 可创建占位测试点。

数据存储在哪里？

默认存储在可执行文件同级目录的 data/ 文件夹，可通过环境变量 CLIJUDGE_DATA_DIR 自定义。题目、文章、比赛、提交分别位于 data/problems、data/articles、data/contests、data/submissions 子目录，旧版平铺数据启动时自动迁移。

如何导入导出题目？

使用 problem export [zip路径] 导出题目，problem import [zip路径] 导入题目。支持 JSON 格式。

沙箱是如何工作的？

双平台多层隔离：Windows 为 Job Object + 受限令牌 + Low IL；Linux 为 namespaces + seccomp + 只读根文件系统 + RLIMIT。评测前进行环境能力预检，在限制非特权 user namespace 的加固系统（如 Ubuntu 24.04）自动降级，仍保留 seccomp 与资源限制；SPJ / 生成器 / grader 以可信（放宽隔离）模式运行并保留时限。
